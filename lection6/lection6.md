### Инструменты для ручного тестирования мобильных приложений

Среда разработки - это комплекс программных средств, используемый программистами для разработки программного обеспечения, который  включает в себя следующие компоненты:

* Текстовый редактор — инструмент, который позволяет разработчикам создавать и редактировать исходный код программы. Он предоставляет функциональность подсветки синтаксиса, автодополнения и форматирования кода, что облегчает написание и чтение кода.

* Транслятор — инструмент, который преобразует исходный код на одном языке программирования в машинный код или исполняемый файл.

* Средства автоматизации сборки (CI) используются для автоматизации процесса сборки и интеграции кода в проект. Они позволяют разработчикам быстро и безопасно создавать новые версии программного обеспечения.

* Отладчик — инструмент, который позволяет разработчикам находить и исправлять ошибки в их программном обеспечении. Он позволяет остановить выполнение программы на определенном месте и пошагово проверять состояние программы во время выполнения.

 
Среда разработки даёт следующие возможности для тестировщиков:

* просмотр кода и создание сборок;
* имитация разных сетевых подключений;
* имитация геокоординат или маршрута;
* инструменты изучения использования ресурсов;
* работа с графикой;
* просмотр логов подключённых устройств и симуляторов/эмуляторов.

**Xсode**
Для чего нужен тестировщику:
* Разработка приложений на платформе iOS
* XCTestCase - создание тест кейсов для автотестирования и прогон их
* Логирование и debug-режим
* Установка сборки на устройство
* Симулятор разных видов девайсов iOS ( просмотр UI, замедление анимации, слои в приложении)
* Просмотр информации о производительности приложения, симуляция Out of Memory, подмена геолокации при тестировании
* Поддержка нескольких симуляторов, которые взаимодействуют друг с другом(  как пример запуск имитации watchOS, чтобы протестировать его связь с приложением)

**Android Studio**
Что доступно для тестирования:
* Логирование и debug-режим, запуск автотестов
* Установка сборки на устройство
* UI. Слои в приложении. Анимации
* Производительность
* Симуляция Out of Memory

* Уровень заряда батареи, входящие звонки и СМС

**Android Debug Bridge**

Android Debug Bridge (ADB) — утилита командной строки для доступа к устройствам на Android.

Android Debug Bridge (ADB) входит в состав Android Studio, но возможна его отдельная установка.

Функции:
* platform-tools
* устанавка, копирование, удаление файлов
* устанавка приложения на устройство, прошивка программ и составляющих элементов системы
* запись видео или скриншоты экрана устройств
* отладка при сбоях в работе устройства
* формирование логов
* предоставление полного доступа к данным об ОС и самом устройстве

Основные команды для работы:
* adb devices - вывести список подключённых устройств
* adb install com.app.example - установить приложение ( необходимо скачать приложение в папку с adb либо указать полный путь к файлу)
* adb install -r com.app.example - переустановить приложение с сохранением пользовательских данных
* adb uninstall com.app.example - удалить приложение 
* adb logcat > logcat.txt  — вывести и сохранить все логи устройства
* adb logcat com.app.example — вывести логи конкретного приложения (adb logcat | Select-String -Pattern "com.fitifyapps.bwcardio"  или adb logcat | grep  "com.fitifyapps.bwcardio" - команды для добавления названия приложения в логи)
* adb shell screencap /sdcard/screenshot.png — создать скриншот(пример пути к файлу)
* adb shell screenrecord /sdcard/video.mp4  — создать скринкаст(пример пути к файлу)
* adb tcpip 5555  — установить соединение по протоколу TCP/IP через порт 5555
* adb connect 192.168.0.100  — подключиться к устройству без кабеля: узнать IP-адрес устройства можно в настройках в разделе «О телефоне»


**Как подключить устройство без USB-кабеля (пример: SmartTV)**
1. Убедиться, что устройство и ваш ПК в одной Wi-Fi-сети
2. Набрать adb tcpip 5555
3. Набрать adb connect IP_устройства:5555

**Monkey**

Monkey — это инструмент командной строки, который можно запустить на любом экземпляре эмулятора или на устройстве. Он отправляет в систему псевдослучайный поток пользовательских событий, который действует как стресс-тест разрабатываемого вами прикладного программного обеспечения.

$ adb shell monkey -p name.app -v 1000 --throttle 500 > monkey_test.txt

1. -v, -v -v, -v -v -v - в командной строке увеличивает уровень детализации. Уровень 0 (по умолчанию) предоставляет мало информации, кроме уведомления о запуске, завершении теста и окончательных результатах. Уровень 1 предоставляет более подробную информацию о тесте во время его выполнения, например об отдельных событиях, отправляемых в ваши действия. Уровень 2 предоставляет более подробную информацию о настройке, например, о действиях, выбранных или не выбранных для тестирования.

2. --throttle <milliseconds> - вставляет фиксированную задержку между событиями. Вы можете использовать эту опцию, чтобы замедлить Обезьяну.

3. --help - помощь

4. -s 5,6,8,2 - Начальное значение для генератора псевдослучайных чисел. Если вы повторно запустите Monkey с тем же начальным значением, он сгенерирует ту же последовательность событий
